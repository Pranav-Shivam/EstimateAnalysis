# Running the project on a new machine

Everything the project needs is in the repository, including the results of the paid LLM steps, so a fresh machine needs no API spend to reach a working demo.

## What travels with the repo

| Data | Where | How it is loaded |
|---|---|---|
| Catalog, customers, pricing, structure | `backend/data/*.json` | `scripts/load_data.py` |
| SKU embeddings (650) and community summaries (56) | `backend/data/llm_snapshot.json.gz` (4 MB) | `scripts/restore_llm_data.py` |
| Judge threshold and calibration | `backend/data/judge_calibration.json` | read directly by the judge |
| Neo4j graph | rebuilt from Postgres | `POST /v1/graph/rebuild` |
| Demo quotes | generated by scripted stand-ins, no LLM | `scripts/seed_demo.py` |

## Fastest way: one command

With Docker installed, from the repo root:

```bash
docker compose up --build
```

This starts Postgres and Neo4j, runs a one-shot setup container, then starts the API, the correction worker and the web app. The setup checks before it acts, so a second start changes nothing: it applies migrations, loads the reference data and the saved LLM output only if the database is empty, seeds the demo quotes only if none exist, and rebuilds the graph only if it is stale or something changed. When it finishes:

- Web app: http://localhost:7050
- API: http://localhost:7060 (docs at /docs)
- The review queue shows 4 open flags.

No API key is needed. Set `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` in your shell before `docker compose up` only if you plan to run a paid step. To change host ports (for example if 7050 or 7060 is taken), set `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`, `NEO4J_HTTP_PORT` or `NEO4J_BOLT_PORT`. `docker compose down` keeps the data; `docker compose down -v` deletes it. The first start is slow because Neo4j downloads its graph plugin, and it needs internet.

Verified on 2026-09-30 in a Linux Docker engine (WSL Ubuntu): first start reached the same state as the manual steps below (4 open flags, 650 SKU nodes, 2506 graph edges), and a stop and start kept the data.

The rest of this file is the manual route, for developing the backend or frontend outside containers.

## Prerequisites

Docker Desktop, Python with `uv`, and Node 20.19+ or 22.12+.

`backend/.env` is git-ignored, so create it on the new machine. The settings loader requires `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` to be present, but the steps below never call either API, so any non-empty value works until you run a live LLM step (embedding, summarizing, calibration, or a real pipeline run). Real keys can come from your key vault.

## Steps

```bash
# 1. databases only, from the repo root
docker compose up -d postgres neo4j

# 2. schema and reference data, from backend/
cd backend
uv run alembic upgrade head
uv run python scripts/load_data.py

# 3. the LLM-produced data, no API call
uv run python scripts/restore_llm_data.py

# 4. demo quotes (dry run without --yes)
uv run python scripts/seed_demo.py --yes

# 5. API on :7060, then rebuild the graph so quotes and communities are in Neo4j
uv run python main.py
curl -X POST http://localhost:7060/v1/graph/rebuild

# 6. UI on :7050, from frontend/ in a second terminal
cd ../frontend
npm install
npm run dev
```

Step 3 must come after step 2: the snapshot refuses to load if its SKUs are not in the database, since embeddings attached to the wrong products would make vector search quietly wrong.

## Checking it worked

- `uv run python scripts/embed_skus.py` (dry run) should say `0 SKUs need an embedding`.
- `http://localhost:7060/v1/graph/stats` should show 650 SKU nodes.
- The UI review queue should show 4 open flags.

## Refreshing the snapshot

After re-running `embed_skus.py --yes` or `summarize_communities.py --yes`, run `uv run python scripts/export_llm_data.py` and commit the new `llm_snapshot.json.gz`.

## Tests on a machine that already holds the demo data

Two acceptance tests (`test_phase2_acceptance`, `test_phase7_acceptance`) count absolute rows and fail when the database already holds the seeded demo quotes. Run the suite against a database that has only `load_data.py` applied.
